# TEARDOWN READY -- 2026-09-24, 4x H200 box

Everything from this session is on `unparallelled/blutrain-680m-reach`.
Nothing on the box is needed to reproduce or continue.

## What this session established

1. **Data composition causes the 680M's short retrieval reach.** Same parent
   (step 3400), same 600 steps, same 1,048,576 tok/step, same LR curve. Only the
   corpus differed. Raw FLUX bought nothing; documents >= 4096 tokens moved
   induction NLL at d=2048 from 3.265 -> 2.013 and NIAH T=4096 from 59 -> 67.
2. **The gain is NOT monotonic in training time.** A second 600 steps
   (4000 -> 4600) gave back ~1/3 of it at every distance, INCLUDING d=256, while
   val loss improved past the base. Keep step 4000.
3. **Scale removes the constraint.** The 1.59B / 8.4B-token curriculum model has
   essentially no in-window retrieval problem: 0.199 / 0.128 / 0.109 / 0.224
   nats at d=256..2048, vs the 680M base's 0.405 / 0.466 / 0.991 / 3.265.
4. **Loss and reach are opposed.** Three consecutive observations. Selecting
   long-context checkpoints on validation loss selects against reach.

## MEASUREMENT CORRECTION -- read before reusing any d=4096 number

The induction probe's d=4096 cell uses T=8192 windows, which is DOUBLE the 4096
pretraining context. At YARN_SCALE=1 that cell measures RoPE extrapolation, not
reach, and every model fails it for that reason. The valid in-window comparison
stops at **d=2048**. Earlier reports in this repo quote d=4096 without this
caveat; treat those cells as extrapolation results.

## To resume on a fresh box

```
./handoff/SETUP_H200.sh          # patch + build + fetch data + build flux_long
```
Then fix two things the handoff gets wrong on a new box:
1. Every handoff script hardcodes `/root/adhi/BluTrain` (lowercase). This box was
   `/root/Adhi/BluTrain`. Linux is case-sensitive -- sed the paths.
2. Checkpoints are 6.7 GB each and BLU_CKPT_FREQ=100 with KEEP=10 needs 40 GB.
   Use `treatment_4600/scripts/janitor.sh` (KEEP=2 or 3).

The corpus is NOT stored (3.4 GB, deterministic). Rebuild:
```
envv/bin/python handoff/scripts/mk_flux_long.py --src stage/dl/flux \
    --out stage/flux_long --lo 37 --hi 100 --min-len 4096
```
-> 1,693,835,604 tokens, 217,533 docs, 0 duplicates, 18 shards. Lay out 12/4/2
across commoncrawl/code/math (SETUP_H200.sh step 5).

Induction streams are also deterministic: `mk_repeat.py --lengths 512 1024 2048
4096 8192 --windows 64` (seed 1234, VOCAB 50256).

## Known traps (cost real time this session)

- `BLU_CKPT_WEIGHTS_ONLY=1` resumes the STEP COUNTER, and the mixed loader
  fast-forwards to match. Run 1 skipped 27,200 batches, run 2 skipped 32,000.
  That is what keeps consecutive legs disjoint -- but it also means a run never
  starts at token 0 of its corpus.
- `CP_DATA_ROOT` / `BLU_MIX_ROOT` need BOTH a train and a **val** split. A
  train-only directory dies with `no .bin shards found for split val`.
- NIAH `HAY` must point at a real corpus shard. Unset, the filler inflates the
  base from 59 to 94 at T=4096 and makes "no improvement" unfalsifiable.
- `run_longeval.sh` never sets `CP_GLOBAL_BATCH`; any T not dividing 524288
  aborts in ~14 s. `niah_one.sh` sets it to `T * 64`.

## Next experiment

the reversion was LR annealing settling the model into its general-purpose
optimum. If it still reverts, reach is transient under distribution shift and
needs an objective change (intra-doc masking), not a data change.
